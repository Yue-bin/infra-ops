# 运维工作区初始化

当前上下文没有 `infra-ops-core` 时，调用 `skill` 工具加载它；已有则直接沿用。本入口只在**当前工作区目录**内工作，不指定外部目录，也不向宿主注册工作区。

## 任务形态

把现场变成可工作的运维工作区：接连接、采最小画像、建立项目约定与状态基线。不做目标机超出 `/tmp` 的写、不写全局 SSH 配置或连接清单、不代替 `infra-apply` 实施变更、不自行提权。

## 推进方式

1. **本地只读预检**。盘点当前目录现状、已有约定与 `AGENTS.md`、是否已在 Git 仓库内；查找可复用连接（宿主 SSH 工具的主机清单、`~/.ssh/config`）。用户调用时已提供的连接方式直接使用，不重复询问。
2. **补齐缺失信息**。缺目标、约束或连接方式时，按核心规则用宿主提问工具询问；先做不违反既有规则的只读探测，再问真正缺失的决策。秘密默认只用于当次连接，渠道由用户当次选择；仅当用户明确要求降级时才落盘，并说明后果与入库边界。
3. **连接与采集**。接受连接时向用户说明：采集只跑只读命令，会在目标机 `/tmp` 建独立临时目录并在结束后清理。通道优先序：已配置的宿主连接工具 → 用户在自己终端交互执行 agent 交付的命令 → agent 直接普通 ssh（仅限密钥或 agent 认证；密码绝不进入命令行、环境变量赋值或 askpass 文件）。普通 ssh 使用工作区级 `UserKnownHostsFile`，主机密钥校验任何情况下不关闭。最小画像只到"能接态"：主机身份、系统、硬件与磁盘、网络、关键服务与版本、挂载与数据面、既有文档位置；方案性结论留给 `infra-design`。
4. **尊重存量**。已有文档、脚本、目录只盘点不覆盖，语义到实际路径的映射写入约定；冲突交用户决定。重复运行幂等：只补缺失、更新重新核实的事实，保留人工修改。
5. **确认 Git 与证据策略**。先查项目是否已有 Git 与远端及既有约定，没有约定时向用户确认远端情况，再据此推荐录制原文的入库策略（无远端默认入库、私有远端默认索引-only、公开远端强制索引-only），写入 `AGENTS.md`。同时在 `AGENTS.md` 写「录制手段」一节：Linux 用本套件约定的 `script` 语法；其他平台须实测等价手段后填写，未填写视为不具备录制能力（见核心 `references/recording.md`）。
6. **先交计划再落盘**。形成精确初始化计划：将创建/修改文件的完整清单与内容（含 `AGENTS.md` 草案、最小 `.gitignore`、状态首版）、目标机临时目录与清理方式、保留项与理由。一次确认覆盖该组动作，偏离重新确认；本地 `git init` 与首提交单独确认。多台机器部分不可达时按带未知项基线收口：已完成部分照常落盘，未达主机与未验证项明确标注并进入 todo，首提交信息如实写明覆盖范围。
7. **落盘与首提交**。按 [references/skeleton.md](references/skeleton.md) 的默认骨架创建文件：项目已有约定优先并可覆盖，空白工作区首次只建根文件与地图，容器出现第一份内容时再建。已有 Git 仓库则沿用，不嵌套新建。

## 完成条件

- 后续 `infra-design` / `infra-apply` 无需聊天记录即可接态：连接约定、环境基线、目录约定、状态入口、录制手段与证据策略齐备；
- 未知主机与未验证项已标注并进入 todo；目标机 `/tmp` 临时目录已清理或记录保留理由；
- 无未授权远程写、无秘密落入任何将入库的文件。

用户要求继续方案或交付时，说明目标扩展并加载 `infra-ops` 进行跨阶段编排；否则在初始化完成处停止。
