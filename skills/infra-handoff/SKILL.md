# 可行动的交接与状态收敛

当前上下文没有 `infra-ops-core` 时，调用 `skill` 工具加载它；已有则直接沿用，不重复加载。

## 任务形态

把持续装维、排障或变更的工作状态整理成新读者可接手的事实与行动集合。遵循项目已有文档和 Git 约定，不复制固定模板。

## 推进方式

1. 读取核心的 `references/state-and-git.md`，接管当前 todo，确认用户要求的交接对象、范围和读者。
2. 对照机器实况、现有状态权威和过程记录，区分当前事实、历史过程、推断与未验证项；不以旧文档覆盖新观测。
3. 收敛当前目标、关键事实及核实时间、决策与确认人、已接受风险、已完成/部分完成/未开始事项和下一步。
4. 检查长日志与观测结果只有必要摘要和受控位置进入主记录，未决 todo 都有负责人和可执行动作。
5. 项目已授权 Git 工作流时，按语义做中文约定式原子本地提交并复核实际入库清单；远端与历史改写保持另行授权。
6. 以新读者视角做一次恢复检查，确认其无需聊天记忆即可找到事实、证据、授权边界和下一动作。

## 完成条件

- 当前状态、决策、风险与未决项各有唯一权威位置，todo 与之不矛盾；
- 每个关键数字和结论都能追溯到证据或重新生成的方法；
- 新读者能直接继续下一步，并识别仍需人决策或执行的边界；
- 本地提交只包含相关文件，无关材料、原始长日志和敏感现场信息没有被夹带入库。
