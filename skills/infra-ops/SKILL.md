# infra-ops 自动 / 混合编排

本入口只持有用户目标、阶段选择与组合，不复制共享核心，也不预设一条必须走完的流程。

当前上下文没有 `infra-ops-core` 时，先调用 `skill` 工具加载它一次；已有则直接沿用。按核心建立 todo、确认目标与授权边界后，再选择当前最需要的专用入口。

## 1. 只加载当前需要的入口

| 当前主要问题 | 调用的 skill |
|---|---|
| 工作区尚未初始化：缺连接方式、环境基线或目录约定 | `infra-init` |
| 现状、目标、约束或方案取舍尚未收敛 | `infra-design` |
| 出现异常，原因或检查判据仍不可靠 | `infra-diagnose` |
| 已确认方案需要安装、迁移、升级或变更实施 | `infra-apply` |
| 需要巡检、独立复核或消费方验收 | `infra-verify` |
| 需要状态收敛、窗口收尾或交接 | `infra-handoff` |

目标同时包含多个阶段时，先加载最近的前置入口，不在开始就把全部入口注入上下文。当前上下文已有某个入口时沿用其规则，不为同一阶段重复调用。

## 2. 根据观测选择下一步

每个阶段完成后，对照用户目标与实际证据重新选择：

- 工作区缺接态必需信息（连接方式、环境基线、目录约定）且目标需要落地工作时，先建议 `infra-init`；已有约定的工作区不重复初始化，一次性只读问答不触发。
- 设计已确认且用户要求交付，才进入实施；关键取舍未决时继续设计或请人决策。
- 实施出现意外，先局部诊断；恢复或重新授权后再决定是否继续实施。
- 验证失败时保留现场并诊断，不因已有实施计划就跳过归因。
- 持续排障、装维交付或发生变更时，按需要收敛交接；一次性只读问答不强制补齐所有阶段。
- 用户目标已经达成时停止，不因“还有入口没用过”继续工作。

这些是反馈路径而非固定顺序。任何阶段都不得自动扩大用户目标、关键方案决策权、写授权或高敏资产访问范围；需要扩展时先取得用户确认。

## 3. 混合模式与专用入口升级

默认由主 agent 在当前上下文动态组合，子代理的选用条件与返回要求按核心规则执行。确需派发时，任务书要求子代理自行加载 `infra-ops-core` 与相应专用入口；写决策、计划授权和跨阶段目标变化留在主线程。

从专用入口开始的工作，只有用户原本就要求跨阶段目标或后来明确扩展时，才切入本编排入口。切入时沿用已加载核心，不因入口切换重复注入或重置已有 todo。

## 4. 停止与交付

满足用户目标所需的消费方结果已验证，必要状态、决策、风险和 todo 已更新，且剩余事项都有明确归属后即可停止。无法继续时，报告具体缺少的决策、授权或证据，而不是用重复加载和重复检查制造进展。

最终回答说明实际经过的阶段、关键证据、已执行或仍待授权的动作，以及未验证范围；不声称走过一条预先假设的完整流程。
