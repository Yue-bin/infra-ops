# infra-ops 共享核心

本文件只提供共享约束，不选择生命周期入口。当前上下文已有本核心时直接沿用，不重复加载。

## 1. 先建立可恢复的工作索引

非琐碎任务立即维护 todo list：多步装维、持续排障、任何变更、跨主机工作或大量观测都属于非琐碎任务。

- 宿主有专用 todo 工具就使用工具；没有则按项目已有约定维护一个工作区文件。
- 条目写清阶段、动作、完成条件、阻塞和下一步，保留并行工作的真实状态；不把每条 shell 命令变成一个条目。
- 每个阶段结束即更新；交接时把未决项转成下一位可执行的记录。
- 文件型 todo 的位置与入库方式遵循项目约定，不创建第二套状态权威。

完成标准：任何接手者都能看见当前目标、已完成阶段、当前动作、阻塞和唯一下一步。

## 2. 接态：先确认目标与事实来源

开始调查或设计前，建立以下最小认识：

1. **目标**：用户要解决的问题、消费方可见的成功结果、本次不包含的范围。
2. **现场**：目标系统、环境、当前生命周期阶段，以及已有状态记录、运行手册、窗口记录和 Git 约定。
3. **边界**：授权通道、高敏资产、维护窗口、已知风险和用户保留的决策。
4. **事实基线**：关键声明的观测时间、来源和适用范围。文档是可复核的声明，机器实况是判断当前状态的依据。

只读事实由 agent 主动调查；只把目标、约束和高影响取舍交给用户决定。已有结论先检查时效与适用环境，不用记忆代替当前观测。

## 3. 观测自治，同时控制上下文

- 按**实际副作用与资产敏感度**分类操作，而不是按命令名称。用户限定的高敏资产即使只读也只交付命令；副作用未确认时按写操作处理。
- 长输出先保存到项目约定的位置，再检索和读取必要片段；同一材料没有失效就不重复全量读入主上下文。
- 长测量和长跑任务使用后台任务并记录任务标识；需要等待时先推进独立工作。
- 只有独立、值得并行或需要隔离偏见的只读调查才派子代理。子代理需自行加载本核心，返回结论、证据摘要、文件位置和未知项，而非原始日志全文。
- 结论明确区分**实测 / 推断 / 未知**；数字同时带目标、时间窗、分母、操作者与来源。

遇到空输出、零计数、异常码、相互矛盾的来源、高影响结论或验收判据时，读取 [references/evidence.md](references/evidence.md) 并应用其中的判据验证规则。

## 4. 方案与写操作共用一道授权门

agent 可自主调查、计算和推荐；用户确认目标、约束及高影响方案取舍。方案不得依赖虚构需求或未核实的现场假设。

规划或执行任何写操作前，读取 [references/change-safety.md](references/change-safety.md)，并形成精确变更计划：命令、目标机、对象集合与上限、影响、恢复依据、验证方法和执行者。

- 一次授权只覆盖该计划；命令、目标、对象、数量上限或用途偏离时重新授权。
- agent 只执行低爆炸半径且有备份或等价保障、明确逆操作和后置验证的写。
- 删除、批量、权限、共享基础设施、不可逆或恢复依据不足的操作由人执行；agent 提供命令与只读复核。
- 每步后读取消费方或目标资源的真实状态；退出码只说明命令结束，不说明目标已生效。

## 5. 持续工作留下状态与决策

持续排障、装维设计或任何变更必须维护当前状态与关键决策；一次性只读问答不强制落盘。项目已有约定优先，不强制固定文件名、表格或目录树。

当前状态只有一个权威入口，至少能回答：事实最后何时从哪里核实、为何这样决策、哪些风险已被谁接受、还有什么未决、证据在哪里。Git 历史保存演变，不构成多个“当前副本”；机器仍是当前事实源。

需要落盘、使用 Git、收敛 todo 或交接时，读取 [references/state-and-git.md](references/state-and-git.md)。

## 6. 以用户目标闭环，而非遍历流程

每个动作后比较预期后置条件与实际观测。偏离时缩小范围做局部归因，再选择继续、回退、重新设计或请人决策；不预设唯一技术路线。

只有用户目标本身跨阶段或后来明确扩展时才扩大工作范围。满足以下条件即可停止，不强制遍历所有生命周期阶段：

1. 用户要求的消费方结果已经验证，或未验证部分已明确标注；
2. 必要的状态、决策、风险、todo 与证据位置已更新；
3. 剩余事项都有明确负责人和下一动作，或已作为未决限制如实交付。
