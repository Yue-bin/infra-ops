# 证据与归因约定

用于空输出、零计数、异常码、数字统计、来源冲突、高影响结论和验收判据。目标是用足以推翻结论的证据缩小不确定性，而不是堆积支持既有猜测的输出。

## 1. 统计之前先划边界

任何计数、比例、速率或损失规模先记录四个边界：

- **时间窗**：起止时间、时区、维护窗口和受控停机是否包含。
- **对象与分母**：统计哪一类对象，分母来自同一工具、同一版本和同一语义。
- **操作者**：区分真实故障、用户操作、其他任务和 agent 自己刚产生的日志或失败。
- **来源与单位**：原始字段含义、单位、采样时刻和去重规则。

完成标准：另一位调查者能不靠对话重算出同一口径。边界改变时把它视为新统计，不与旧数字直接比较。

## 2. 先验证判据，再解释结果

### 阳性对照

用一个已知含有目标特征的样本，确认检查手段确实能检出它。空文件、空列表、零匹配或“没有错误”只有在探针能命中已知样本时才有证明力。

### 阴性对照

用一个已知正常的样本，确认检查手段不会恒报异常。异常码、错误文本和高失败率先排除“这个工具对任何输入都这样报”。

### 语义与路径

核对当前版本的官方文档、`--help` 或实现，确认输入路径属于哪个命名空间、字段表示什么、错误在哪些情况下也会误报。本地路径、服务 API 路径和对象键不能只因字符串相似就互相替代。

### 独立路径

高影响结论用另一条真正独立的读取路径复核，例如从“扫描工具报告对象缺失”走到消费方实际读取。重复调用同一工具、同一缓存或同一损坏数据源不算独立复核。

## 3. 按结论风险分配验证成本

以下结论至少需要判据验证和独立路径复核：数据丢失、故障影响面、安全暴露、不可逆操作依据、重大容量或成本决策，以及会直接触发用户报警的数字。

常规低影响观测可使用一条已理解且可靠的来源；一旦出现矛盾、边界变化或要升级为高影响结论，就补足验证。推断必须附带能推翻它的下一项检查，无法验证时保留为未知。

## 4. 让解析错误先暴露

- 优先使用结构化解析器或工具的稳定机器输出，不依赖 JSON 字段顺序、相邻行数或“大概在附近”的文本位置。
- 正则、过滤器和采样查询先在已知阳性样本上演示命中，再在已知阴性样本上演示不误中。
- 空解析结果先检查输入是否存在、格式是否变化、表达式是否匹配，再讨论业务含义。
- 抽样结论写清总体、抽样方法、样本量和能外推的范围；逐份差异需要逐份验证时，不用汇总值代替。

## 5. 动态归因，而非固定顺序

同时保留能解释同一现象的多个候选：目标或参数语义、配置漂移、缓存与重试、工具限制、统计口径、外部依赖、物理层，以及调查者自己的动作。

下一项测试按以下标准选择：

1. 能否明确支持或推翻某个候选；
2. 观测代价与对现场的风险是否足够低；
3. 能否最快缩小高影响未知范围；
4. 是否使用了与先前失败不同的信息路径。

每次测试后更新“支持了什么、削弱了哪项、仍不知道什么”。硬件、软件或工具都不因个人偏好获得固定优先级。

## 6. 控制证据的上下文成本

- 原始长日志保存后，用检索、计数、首尾片段和针对性上下文读取定位；正文只保留关键行、统计口径与文件位置。
- 交互进度与可解析记录都需要时，使用能同时保留终端行为和日志的记录方式，不反复粘贴整段输出。
- 长测量后台运行并跟踪任务标识；采样结束后读取目标结果，不用前台长时间等待占住主线程。
- 子代理的选用条件按核心规则；返回物只含结论、证据位置和未知项，主 agent 独立复核高影响结论。

## 7. 匿名反例

- 某正则对真实字段返回空列表；先在已知含该字段的样本上测试后立即发现表达式漏了合法空白，而不是宣布对象不存在。
- 某完整性工具报告大量对象缺失；通过消费方实际读取发现相当部分可正常返回，于是先修正工具位置和覆盖范围，不重报损失规模。
- 某日志突然出现大量认证失败；按操作者与时间窗拆分后发现主要来自调查者自己的错误探测，于是撤回“系统凭据已失效”的结论。

完成标准：每个高影响结论都能回答“用什么判据、在什么边界、经哪条独立路径验证”；每个未知项都有保留下一验证手段的明确表述。
