# 变更与恢复约定

用于方案进入实施、任何可能改变目标环境的命令，以及需要用户执行的命令交付。授权解决“谁允许”，恢复证据解决“失败后能否回来”，两者缺一不可。

## 1. 按真实副作用和资产分类

只读自治适用于不会改变目标状态、且用户允许 agent 直连的观测。命令中的清理、压缩、预热、重载、截断、计数重置或后台任务触发参数，都可能使表面上的查询变成写操作。

用户限定的高敏资产即使只读也由人执行；无法确认副作用、作用域或远端连带影响时，先按写操作对待。网络、共享存储、身份权限和生产控制面的一个本地动作可能产生跨系统影响，分类时看完整副作用链。

## 2. 关键方案决策由人确认

agent 负责把现状、选项、计算、约束和推荐做扎实；用户确认目标、优先级及高影响取舍。每个推荐都应能指出它服务的真实需求，不能先选结构再虚构理由。

涉及拓扑、容量、版本、数据保留、暴露面或不可恢复性的假设，先用一手来源和现场数据核实。存在多个合理方案时呈现取舍与适用条件，不把个人偏好包装成唯一解。

## 3. 精确变更计划是授权单位

计划至少写清：

- 要达成的消费方结果和本次不包含的范围；
- 完整命令、执行环境、目标主机、对象集合及数量上限；
- 依赖、stdin/TTY/变量展开等执行条件，以及目标机上的可用性证据；
- 影响面、预期中断或抖动、远端连带影响；
- 备份或等价恢复保障、逆操作、恢复成功的判据；
- 每步后置验证、最终消费方验证和异常时的停止条件；
- 哪些步骤由 agent 执行，哪些由人执行。

可执行命令不混放待替换占位符。交互式粘贴、非交互 shell、定时任务和后台任务对输入与环境的假设不同，交付时按实际执行方式检查。广播命令必须对集合内每个目标成立，有差异就拆分并明确限定范围。

一次授权只覆盖上述计划。命令、目标、对象、数量、用途或执行窗口偏离时重新授权；对上一目标的许可不自动延续到下一目标。

## 4. 用证据证明可恢复

agent 可亲自执行的写必须同时满足：

1. 爆炸半径低且对象集合可枚举；
2. 变更前状态已保存，或有经过核实的等价重建来源；
3. 逆操作明确、依赖存在，恢复成功可从目标状态读出；
4. 后置验证能发现部分成功、延迟生效和静默失败；
5. 用户已授权这一精确计划。

风险或恢复不确定性升高时，先在隔离环境演练，或把执行交给人。以下操作不因为写了“回滚命令”就自动获得 agent 执行资格：删除与覆盖、批量修改、属主/权限/ACL、共享基础设施、不可逆迁移，以及任何无法证明恢复路径的操作。

dry-run 用来核对计划形态，不替代备份完整性、目标环境依赖和真实后置验证。回滚同样需要有界授权，不以“恢复原状”为名扩大对象范围。

## 5. 执行时逐步对账

- 执行前重新核对当前主机、目标对象和数量，确认它们仍属于已批准集合。
- 每个动作后立即读取预期的目标状态；出现意外对象、意外影响或未知错误时停止扩大动作，保留现场并局部归因。
- 部分成功时分别记录成功、失败和未尝试对象，不用总体退出码掩盖中间状态。
- 长任务后台化并保留可追踪标识；终止进程先枚举并核对 PID 与影响，再按明确目标执行，避免模式匹配误伤执行者自身。
- 人执行的步骤由 agent 提供影响、恢复和验证信息，随后主动读取可见后置状态；信息不可见时明确标注证据缺口。

## 6. 匿名反例

- 某命令块标注“仅主机 A”，却被粘贴到主机 B；此后交付把目标限定写进命令与授权对象，执行前再读当前主机身份。
- 某任务把密码占位符合进后台脚本，造成空跑；此后可执行命令与模板分开，并在执行前验证必需变量非空。
- 某批量标记按集合名称扩大了对象范围；此后先打印并核对精确对象清单，再决定是否有资格执行。
- 某进程终止模式匹配到包装命令自身；此后先列出目标 PID，按明确 PID 和已授权范围处理。

完成标准：计划的每个对象都能追溯到同一次授权，每一步都有实际后置观测，任何未完成或越界风险都没有被“命令执行成功”掩盖。
