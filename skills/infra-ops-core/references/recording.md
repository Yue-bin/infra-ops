# 过程录制与审计约定

让运维过程本身可复核：谁在什么时候、对哪台机器、执行了什么、结果如何，都能从留存的原始记录读出来，而不仅凭聊天摘要。

## 1. 什么时候必须录制

以下任一条命中即强制录制：

1. **改变目标环境状态**：远程主机或**本机服务**上的 systemd/service、容器、数据库、包管理、配置与挂载变更；
2. **长时或交互式命令**：装依赖、批量迁移、全盘扫描、需要进度条或交互输入的工具；
3. **被引用为证据**：其输出将支撑高影响结论、验收结论或损失规模判断。

**不需要录制**：本地文件编辑、Git 命令（Git 自身即审计）、普通短只读查询。录制是有成本的，把每条只读也录下来只会把真正重要的记录淹没。

由人执行的目标环境写操作**同样强制**：交付命令时就带好录制外壳，而不是事后补录。

## 2. 计划内声明

agent 按上述三条自行判定，并在**精确变更或初始化计划里逐条声明**哪些步骤会录制、录到哪里。用户审批计划时同时看到录制范围，因此录制随计划一并获得授权。

无法录制时（平台不适用、本机缺工具、平台手段未在项目约定中登记），**写操作停在计划门**：给出可选路径（等价手段、人工执行、显式接受无记录），由用户决定，不静默降级。

## 3. Linux 语法

```bash
script -q -e -c '<命令>' <证据路径>
```

- `-e` 必须带，否则子命令退出码不透传，失败会被记成成功。
- `-q` 只抑制终端提示，**文件里仍保留** `Script started … [COMMAND=…]` 与 `Script done…` 头尾。原样保留：它们自带时间戳与被执行命令原文，是最好的审计证据，事后不改写。
- 证据路径必须是**项目内持久位置**（见下节命名），不要用 `/tmp`：受限环境里 `/tmp` 可能不跨调用保留。

录制本身失败（文件不可写、封装异常）与子命令失败是两件事：子命令失败只影响该步结果；**录制失败则证据无效**，该写操作不得宣称完成，需修复后重做或显式记为无证据。

## 4. 非 Linux 平台

本约定只定义 Linux 语义。其他平台须先实测等价手段，确认三点后把具体命令写入项目 `AGENTS.md` 的「录制手段」一节：

1. 能同时保留终端行为（进度、颜色、交互）与可解析日志；
2. 透传子命令退出码；
3. 生成可长期保存的普通文件。

**未写入即视为该环境不具备录制能力**，按第 2 节的停写规则处理。不要凭印象假定某平台的旗标与 Linux 相同。

## 5. 产物与命名

```
evidence/<YYYY-MM-DD>T<HHMMSS>-<host>-<slug>.log
```

- 日期加时刻共同构成排序键，不用数字前缀；
- `<host>` 用项目内已登记的主机名或别名，`<slug>` 是简短用途短语；
- 路径与命名沿用项目约定，本约定只在项目无约定时提供默认。

## 6. 证据索引

在项目约定的证据位置维护索引（默认 `evidence/index.md`），每份录制至少记录十项：时间、主机、用途、相对路径、退出码、SHA-256、字节数、是否入库、秘密审阅结论、关联的窗口或变更。

索引让后续接手者不必逐个打开大文件即可判断：是否有证据、是否完整、是否可信、在哪里。原始文件按第 7 节策略决定是否入库，索引本身应始终入库。

## 7. 入库策略

初始化时先确认项目是否有 Git、是否设远端，再据此推荐（用户确认后写入 `AGENTS.md`）：

| 情形 | 推荐 |
|---|---|
| 无 Git 或无远端 | 原文默认入库：本地留存几乎免费，删掉就再也没有了 |
| 私有远端 | 默认只入索引，原文留本地；显式授权后才入库 |
| 公开远端 | 强制索引-only，原文不入库 |

**提交粒度**：录制文件与索引随所在窗口或语义变更的里程碑提交一起入库，不为每条命令单独提交，否则历史会被噪声淹没。

**秘密**：录制会记录命令行原文，因此秘密（密码、令牌、口令）不得出现在命令行参数、环境变量赋值或 askpass 文件中。入库前必须逐份做秘密审阅，并把结论写进索引；含秘密的记录不得入库，且应视为已经泄漏，需要轮换。
