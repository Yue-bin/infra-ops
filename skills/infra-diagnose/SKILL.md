# 证据驱动的故障诊断

当前上下文没有 `infra-ops-core` 时，调用 `skill` 工具加载它；已有则直接沿用，不重复加载。

## 任务形态

解释异常并缩小不确定性。默认完成诊断而非自动修复；只读观测自治，高敏资产和任何写操作仍服从核心边界。

## 推进方式

1. 按核心建立 todo，确认用户看到的现象、消费方影响、目标范围、时间窗和已知维护动作。
2. 保存原始证据并划定对象、分母、操作者、单位和来源；将 agent 自己的探测从系统既有故障中区分出来。
3. 遇到空输出、零计数、异常码或数字结论时读取核心的 `references/evidence.md`，先做阳性/阴性对照并核对工具语义。
4. 同时保留多个可解释现象的候选，按可证伪性、观测代价、风险和信息增益选择下一项只读测试。
5. 高影响结论通过独立读取路径复核；出现矛盾时先审查判据与边界，再更新候选，不挑选支持既有猜测的片段。
6. 给出实测支持的归因、仍属推断的部分和剩余未知；若用户随后要求修复或完整处置，说明目标扩展并加载 `infra-ops`。

## 完成条件

- 统计口径可复算，关键判据经过验证，高影响结论有独立证据；
- 结论能解释已观察现象，也说明不能解释或尚未覆盖的部分；
- 每个主要候选都有支持、削弱或未决状态，下一项最有信息量的检查明确；
- 原始证据有位置，主上下文只保留必要片段，持续诊断的状态与 todo 已更新。
